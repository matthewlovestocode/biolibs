# @biolibs/dseq

Double-stranded DNA and RNA whose ends are part of the molecule: a port of
[pydna](https://github.com/BjornFJohansson/pydna)'s `Dseq`.

Where `@biolibs/seq`'s `Seq` is one strand of letters, a `Dseq` knows what is opposite every base. A
restriction fragment's sticky ends, a blunt end, a nick and a single-stranded stretch are states the
molecule carries, so ligating two fragments can refuse ends that do not pair instead of quietly joining
strings. pydna is the second upstream library this repo ports, and it is measured the same way: see
[docs/parity-pydna/](parity-pydna/README.md).

## The encoding

pydna holds a molecule as one letter per base pair — its "dscode" alphabet. `G` is a G over a C, `P` is a
G on the upper strand with nothing opposite it, `Q` is a C on the lower strand alone, `0`–`9` are loops
and `!`–`;` mismatches. Reading a strand off is then one translation table and finding the overhangs is
one regular expression, which is what `alphabet.ts` does. The tables come from pydna itself, generated by
`reference/gen_pydna_data.py` into `src/data/dscode.ts`; never edit that file by hand.

```ts
import { Dseq } from "@biolibs/dseq";

const blunt = new Dseq("GAATTC");          // six base pairs, both ends blunt
blunt.figure();                            // "Dseq(-6)\nGAATTC\nCTTAAG"

const cut = new Dseq("PPPPGAATTCQQQQ");    // a 5' overhang at each end
cut.fivePrimeEnd();                        // ["5'", "gggg"]
cut.ovhg;                                  // -4
cut.looped().circular;                     // true — the ends pair, so it closes

new Dseq("GAATTC").add("GGG").toString();  // "GAATTCGGG"
Dseq.fromRepresentation("GAATTC\n  TAA").crick;   // "AATTC"
```

Cutting is free functions rather than methods so that `Dseq` itself does not have to know about enzymes,
which keeps the two modules from importing each other. The enzymes are `@biolibs/restriction`'s, so a
Type IIS enzyme that cuts away from its recognition site works the same way it does in pydna.

```ts
import { cut, Dseq, getCutsites } from "@biolibs/dseq";
import { enzymes } from "@biolibs/restriction";

const plasmid = new Dseq("AAGAATTCAAGGATCCAA", null, null, true);   // circular
getCutsites(plasmid, [enzymes.EcoRI]);      // [{ watson: 3, ovhg: -4, enzyme: EcoRI }]
cut(plasmid, [enzymes.EcoRI, enzymes.BamHI]).map((f) => f.figure());
```

## What this slice covers, and what it does not

Ported and measured against pydna 5.5.16: construction from one strand, from two strands with an explicit
or an inferred overhang, from a full sequence with overhangs and from a drawn representation; both
strands; the overhang at each end; the blunt reading; the figure, long runs shortened as pydna shortens
them; the parts; the ends; bluntness; molecular weight; reverse complement; filling an end in;
circularising and rotating a circle; ligation and repetition; equality; slicing, wrapping round the
origin for a circle; and cutting — the cut sites, which of them are possible, how they pair up, every
fragment, the ends written as cut sites, and the cutter counts.

The enzymes that change an end are here too: filling a recessed 3' end in (`fillIn`, `klenow`), bringing
both ends to blunt (`t4`, which fills a 5' overhang in and chews a 3' one back), throwing the
single-stranded ends away (`mung`, `nibbleToBlunt`), chewing one strand back from one end (the four
`nibble*` functions, and `exo1Front` / `exo1End` under pydna's older names), adding a tail
(`terminalTransferase`, one A by default, which is what readies a fragment for TA cloning) and excising
uracils (`user`).

Melting is here as well. A short double-stranded stretch held between single-stranded ones lets go before
a long one does, so `melt(d, length)` finds every stretch of up to `length` base pairs that would come
apart — with one pattern over the dscode string for a stretch that comes away as a single strand and
another for one whose two sides stay double stranded — sheds the single strands first, then breaks what
is left at each site, widening every cut over the single-stranded stretch beside it so that the fragment
keeps it. `getSsMeltsites`, `getDsMeltsites`, `meltSsDna`, `shedSsDna`, `shiftMeltCutsite` and
`shiftMeltCutsitePairs` are the steps, available on their own.

Not yet: `seguid` (which needs the separate `seguid` package's checksums for linear and circular
double-stranded molecules), `join`, `find`, `__contains__` and `__hash__`. `docs/parity-pydna/` is the
current list.

Quirks kept because pydna has them, each pinned by a golden case:

- `Dseq("") + "GGG"` gives back the string `"GGG"`, not a molecule: pydna returns a copy of the other
  operand without looking at what it is. `add` is typed `Dseq | string` for that reason.
- `mw()` has no weight for an ambiguity code, a loop or a mismatch, so it throws `KeyError` for a
  molecule the rest of the API handles.
- Annealing two strands where the second is empty raises `ValueError: zero-size array to reduction
  operation maximum which has no identity`, which is pydna's suffix-array extension failing before it can
  report that the strands do not anneal.
- `representationTuple` shortens what it calls the right 5' overhang with the 3' placeholder and the other
  way round, because pydna unpacks the parts into its own names in the wrong order.
- A circle's slices wrap, and a stop that is not past its start means a whole turn rather than nothing, so
  `circularSlice(data, 4, 2)` reads all the way round. `circularShifted` is written on top of those slices
  as `d[shift:] + d[:shift]`, which means a shift larger than the circle returns something *longer* than
  the circle; `replaceWith` inherits the same behaviour. An empty circle has no length to divide by, so
  `circularShifted` throws `ZeroDivisionError`.
- The cutter counts (`cuttersBy`) search the molecule as a linear one whatever its topology, because pydna
  leaves Biopython's `linear` argument at its default there — so a circular molecule's counts miss a site
  that straddles the origin even though `getCutsites` finds it.
- A single-stranded molecule has no overhang, so `leftEndPosition` and the end-as-cut-site helpers throw
  `TypeError: '>' not supported between instances of 'NoneType' and 'int'`, which is Python comparing
  `None` with a number.
- `CircularBytes.replace_with` concatenates its replacement onto a byte string, so in pydna it can only be
  called with `bytes`; given a `str` it always raises. `replaceWith` here takes a string, which is the
  path pydna's own code uses.
- `fillIn` and `t4` disagree about an empty list of bases: `fill_in` only treats `None` as "all of them",
  so `fillIn(d, "")` adds nothing, while `T4` tests for falsiness and so takes `""` as all of them.
- `fillIn` on a single strand throws `TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'`,
  because it adds the length it filled to an overhang that is not there. `t4` on the same molecule works,
  since it never looks at the overhang.
- Melting at a length below one builds the quantifier `{1,0}`, which no regular expression engine will
  take, so `getSsMeltsites` and anything that goes through it throw `PatternError: min repeat greater
  than max repeat at position 68` — Python's own complaint, position and all. `getDsMeltsites` and `melt`
  check the length first and answer with nothing instead.
