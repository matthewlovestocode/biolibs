# @biolibs/dseq

Double-stranded DNA and RNA whose ends are part of the molecule: a port of
[pydna](https://github.com/BjornFJohansson/pydna)'s `Dseq`.

Where `@biolibs/seq`'s `Seq` is one strand of letters, a `Dseq` knows what is opposite every base. A
restriction fragment's sticky ends, a blunt end, a nick and a single-stranded stretch are states the
molecule carries, so ligating two fragments can refuse ends that do not pair instead of quietly joining
strings. pydna is the second upstream library this repo ports, and it is measured the same way: see
[docs/parity-pydna/](parity-pydna/README.md).

## The encoding

pydna holds a molecule as one letter per base pair — its "dscode" alphabet. `G` is a G over a C, `P` is a
G on the upper strand with nothing opposite it, `Q` is a C on the lower strand alone, `0`–`9` are loops
and `!`–`;` mismatches. Reading a strand off is then one translation table and finding the overhangs is
one regular expression, which is what `alphabet.ts` does. The tables come from pydna itself, generated by
`reference/gen_pydna_data.py` into `src/data/dscode.ts`; never edit that file by hand.

```ts
import { Dseq } from "@biolibs/dseq";

const blunt = new Dseq("GAATTC");          // six base pairs, both ends blunt
blunt.figure();                            // "Dseq(-6)\nGAATTC\nCTTAAG"

const cut = new Dseq("PPPPGAATTCQQQQ");    // a 5' overhang at each end
cut.fivePrimeEnd();                        // ["5'", "gggg"]
cut.ovhg;                                  // -4
cut.looped().circular;                     // true — the ends pair, so it closes

new Dseq("GAATTC").add("GGG").toString();  // "GAATTCGGG"
Dseq.fromRepresentation("GAATTC\n  TAA").crick;   // "AATTC"
```

Cutting is free functions rather than methods so that `Dseq` itself does not have to know about enzymes,
which keeps the two modules from importing each other. The enzymes are `@biolibs/restriction`'s, so a
Type IIS enzyme that cuts away from its recognition site works the same way it does in pydna.

```ts
import { cut, Dseq, getCutsites } from "@biolibs/dseq";
import { enzymes } from "@biolibs/restriction";

const plasmid = new Dseq("AAGAATTCAAGGATCCAA", null, null, true);   // circular
getCutsites(plasmid, [enzymes.EcoRI]);      // [{ watson: 3, ovhg: -4, enzyme: EcoRI }]
cut(plasmid, [enzymes.EcoRI, enzymes.BamHI]).map((f) => f.figure());
```

## What is covered, and what is not

Ported and measured against pydna 5.5.16: construction from one strand, from two strands with an explicit
or an inferred overhang, from a full sequence with overhangs and from a drawn representation; both
strands; the overhang at each end; the blunt reading; the figure, long runs shortened as pydna shortens
them; the parts; the ends; bluntness; molecular weight; reverse complement; filling an end in;
circularising and rotating a circle; ligation and repetition; equality; slicing, wrapping round the
origin for a circle; and cutting — the cut sites, which of them are possible, how they pair up, every
fragment, the ends written as cut sites, and the cutter counts.

The enzymes that change an end are here too: filling a recessed 3' end in (`fillIn`, `klenow`), bringing
both ends to blunt (`t4`, which fills a 5' overhang in and chews a 3' one back), throwing the
single-stranded ends away (`mung`, `nibbleToBlunt`), chewing one strand back from one end (the four
`nibble*` functions, and `exo1Front` / `exo1End` under pydna's older names), adding a tail
(`terminalTransferase`, one A by default, which is what readies a fragment for TA cloning) and excising
uracils (`user`).

Melting is here as well. A short double-stranded stretch held between single-stranded ones lets go before
a long one does, so `melt(d, length)` finds every stretch of up to `length` base pairs that would come
apart — with one pattern over the dscode string for a stretch that comes away as a single strand and
another for one whose two sides stay double stranded — sheds the single strands first, then breaks what
is left at each site, widening every cut over the single-stranded stretch beside it so that the fragment
keeps it. `getSsMeltsites`, `getDsMeltsites`, `meltSsDna`, `shedSsDna`, `shiftMeltCutsite` and
`shiftMeltCutsitePairs` are the steps, available on their own.

`seguidOf` gives the molecule its SEGUID — `cdseguid` for a circle, so the origin does not matter, and
`ldseguid` for a linear one with the overhangs written out as gaps so that a sticky end is part of what is
identified. The checksums themselves are in [@biolibs/seguid](seguid.md).

That completes `pydna.dseq` and `pydna.alphabet`: [the checklist](parity-pydna/README.md) is 102 of 102,
with `__hash__` on both classes marked not applicable, since Python sets it to `None` wherever `__eq__` is
defined without it and JavaScript has no hashing protocol to port. With `pydna.seq`'s 26 items this
package is **128 of 128**, verified by 208 recorded sessions holding 1,717 operations.

`pydna.common_sub_strings`, the homology matcher the assembly stack starts from, is
[`@biolibs/assembly`](../packages/assembly). `pydna.assembly2` itself is not ported: it needs
`pydna.contig` and a provenance model built on pydantic.

See [the package README](../packages/dseq/README.md) for the API with worked examples.

Quirks kept because pydna has them, each pinned by a golden case:

- `Dseq("") + "GGG"` gives back the string `"GGG"`, not a molecule: pydna returns a copy of the other
  operand without looking at what it is. `add` is typed `Dseq | string` for that reason.
- `mw()` has no weight for an ambiguity code, a loop or a mismatch, so it throws `KeyError` for a
  molecule the rest of the API handles.
- Annealing two strands where the second is empty raises `ValueError: zero-size array to reduction
  operation maximum which has no identity`, which is pydna's suffix-array extension failing before it can
  report that the strands do not anneal.
- `representationTuple` shortens what it calls the right 5' overhang with the 3' placeholder and the other
  way round, because pydna unpacks the parts into its own names in the wrong order.
- A circle's slices wrap, and a stop that is not past its start means a whole turn rather than nothing, so
  `circularSlice(data, 4, 2)` reads all the way round. `circularShifted` is written on top of those slices
  as `d[shift:] + d[:shift]`, which means a shift larger than the circle returns something *longer* than
  the circle; `replaceWith` inherits the same behaviour. An empty circle has no length to divide by, so
  `circularShifted` throws `ZeroDivisionError`.
- The cutter counts (`cuttersBy`) search the molecule as a linear one whatever its topology, because pydna
  leaves Biopython's `linear` argument at its default there — so a circular molecule's counts miss a site
  that straddles the origin even though `getCutsites` finds it.
- A single-stranded molecule has no overhang, so `leftEndPosition` and the end-as-cut-site helpers throw
  `TypeError: '>' not supported between instances of 'NoneType' and 'int'`, which is Python comparing
  `None` with a number.
- `CircularBytes.replace_with` concatenates its replacement onto a byte string, so in pydna it can only be
  called with `bytes`; given a `str` it always raises. `replaceWith` here takes a string, which is the
  path pydna's own code uses.
- `fillIn` and `t4` disagree about an empty list of bases: `fill_in` only treats `None` as "all of them",
  so `fillIn(d, "")` adds nothing, while `T4` tests for falsiness and so takes `""` as all of them.
- `fillIn` on a single strand throws `TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'`,
  because it adds the length it filled to an overhang that is not there. `t4` on the same molecule works,
  since it never looks at the overhang.
- A molecule cannot be hashed: Python sets `__hash__` to `None` because `__eq__` is defined without it,
  so `hash(d)` raises `TypeError: unhashable type: 'Dseq'`. A golden case records that refusal; nothing
  in the port answers it, because a JavaScript object is always usable as a `Map` key.
- `find` searches the dscode string rather than either strand, which is what pydna searches: for a fully
  double-stranded molecule that reads as a search of the upper strand, and for one with overhangs it is a
  search of the code. `find` also takes an `end` argument that pydna computes and then never uses, so
  neither does this.
- `seguidOf` on a single strand throws `TypeError: can't multiply sequence by non-int of type 'NoneType'`,
  from writing an overhang that is not there out as gaps.
- Melting at a length below one builds the quantifier `{1,0}`, which no regular expression engine will
  take, so `getSsMeltsites` and anything that goes through it throw `PatternError: min repeat greater
  than max repeat at position 68` — Python's own complaint, position and all. `getDsMeltsites` and `melt`
  check the length first and answer with nothing instead.

## pydna's own single strand: `PydnaSeq` and `ProteinSeq`

Under `Dseq` sits `pydna.seq`, the class `Dseqrecord` and the whole assembly stack are built on. It is a
Biopython `Seq` with a handful of extra questions about a coding sequence, and it is exported here as
`PydnaSeq` because `@biolibs/seq` already has a `Seq` of its own — the same class, under a name that can
sit beside it.

| Python | biolibs | What it answers |
|---|---|---|
| `Seq.gc()` | `gc()` | the G+C fraction, to three decimals |
| `Seq.rarecodons(organism)` | `rarecodons(organism)` | where the organism's rare codons are |
| `Seq.startcodon()`, `stopcodon()` | same | how strong the first and last codons are |
| `Seq.orfs(minsize)` | `orfs(minsize)` | open reading frames in all three forward frames |
| `Seq.orfs2(minsize)` | `orfs2(minsize)` | the readings in frame 0, longest first |
| `Seq.seguid()` | `seguid()` | the SEGUID v2 checksum |
| `Seq.translate()` | `translate()` | the protein, as a `ProteinSeq` |
| `Seq.transcribe()`, `rc()` | same | RNA, and the reverse complement |
| `ProteinSeq.molecular_weight()`, `pI()`, `instability_index()` | `molecularWeight()`, `pI()`, `instabilityIndex()` | `Bio.SeqUtils.ProtParam`'s three measurements |

```ts
import { ProteinSeq, PydnaSeq } from "@biolibs/dseq";

const s = new PydnaSeq("ATGGCCTTTAAATTTGGGTGCTGA");
s.gc();                       // 0.417
s.startcodon();               // 1.0  — ATG, the strongest start in yeast
s.orfs(1);                    // [[0, 24]]
s.translate().toString();     // "MAFKFGC*"
new ProteinSeq("MAFKFGC").molecularWeight();   // 803.0033
```

Several things here are pydna's rather than Biopython's, and are reproduced rather than tidied up:

- `rc` and `reverseComplement` go through pydna's **dscode** table, not Biopython's, so a mixed DNA/RNA
  sequence is complemented instead of refused — `U` comes back as `O`, and dscode letters complement to
  their own partners (`PQGATC` → `GATCIJ`).
- `translate` accepts a `table` argument and then ignores it: upstream builds a fresh Biopython `Seq` and
  passes everything *except* the table through, so asking for another genetic code silently gets the
  standard one. The port does the same, so the same call gives the same wrong answer in both.
- `orfs` and `orfs2` are two different searches, not two spellings of one. `orfs` reads all three forward
  frames and reports positions; `orfs2` is a regular expression over frame 0 alone, restarted one
  character past each hit, and reports the sequences. They disagree about what `minsize` means too:
  `orfs` turns it into a codon count as `ceil(minsize / 3) - 1`, so a limit of 3 asks for no codons at all
  between start and stop, while `orfs2` counts codons directly.
- `startcodon("eco")` is null for an ordinary gene, because pydna's `eco` start table does not list `ATG`.
  Only `sce` has codon weights at all; `rare_codons`, `start`, `stop` and the N-end rule have both. An
  organism with no table at all raises `KeyError` naming it, and for `nEnd` that happens *before* the
  translation, because Python evaluates the dict subscript before the argument.
- `ProteinSeq` refuses `translate`, `complement`, `complementRna`, `reverseComplement`,
  `reverseComplementRna`, `transcribe`, `backTranscribe` and `rc` with
  `NotImplementedError: Not defined for protein.`, and `pI` on an empty protein raises `IndexError:
  string index out of range` from reading a terminal residue that is not there. Slicing either class keeps
  its own class, as Biopython's `__getitem__` does.

The per-organism numbers are generated from pydna by `reference/gen_pydna_codon_data.py` into
`src/data/codon.ts`; never edit that file by hand.

## `cai` and `express`, and the fourth upstream under them

`cai` is Sharp and Li's codon adaptation index: every codon carries a weight saying how close it is to the
organism's preferred synonym, and the score is the geometric mean of those weights, so a sequence of
entirely preferred codons scores 1 however long it is. pydna does not compute it — it calls the `cai2`
package, which asks SciPy for the mean — so what is ported here is that package, in `cai.ts`.

```ts
new PydnaSeq("ATGGCCTTTAAATTTGGGTGCTGA").cai();   // 0.664
new PydnaSeq("CGACGGCCG").cai();                  // 0.15 — three of yeast's rarest codons
```

Three of its habits are worth knowing, because none of them is obvious from the outside:

- **`ATG` and `TGG` are dropped, not scored.** They have no synonyms, so their weight is fixed at 1 and
  counting them would only pull every score towards 1. A sequence of nothing but those codons therefore
  has an empty list to average, and SciPy answers `NaN` while emitting `SmallSampleWarning: One or more
  sample arguments is too small; ...`. `cai("ATG")` is NaN, not 1.
- **A stop codon missing from the weights is skipped; any other missing codon raises** `KeyError: Bad
  weights dictionary passed: missing weight for codon X.`
- **Only `sce` has weights at all.** `cai("eco")` raises `KeyError: 'eco'`, even though `rarecodons`,
  `startcodon`, `stopcodon` and `nEnd` all accept `"eco"` happily.

`express` is the one-row summary built on it: the first and last codons, the length in codons, the index,
the GC fraction, the start and stop strengths, the N-end half-life, a count per rare codon, and the
fraction of the sequence those make up. Note that it asks for the start and stop strengths *without*
passing the organism on, so those two columns are always `sce`'s however it is called.

```ts
const t = new PydnaSeq("ATGGCCTTTAAATTTGGGTGCTGA").express();
lol(t);
// [["cds", "len", "cai", "gc", "sta", "stp", "n-end", "CGA", "CGG", "CGC", "CCG", "CTC", "GCG", "rare"],
//  ["ATG...TGA", 8, 0.664, 0.417, 1.0, 0.3, ">30 h", 0, 0, 0, 0, 0, 0, 0]]
```

Upstream the row comes back inside a `prettytable` table. **That layout is not ported**: the cells are what
pydna computes, and `lol` gives them back the way pydna's own `lol()` does, so the parity cases compare the
cells and claim nothing about the rendering. A sequence shorter than one codon never reaches the division
at the end of `express`, because `cai` has already refused it.

One thing this turned up elsewhere: `round(x, 3)` is not `Math.round(x * 1000) / 1000`. Python rounds a tie
to the nearest *even* digit and decides what a tie is from the double's exact decimal value rather than from
the scaled-up one, so `round(0.0625, 3)` is 0.062 for two separate reasons. `pyRoundTo` in `@biolibs/core`
does it properly, and `gc` uses it now too.
